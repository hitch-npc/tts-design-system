# sprite-to-webm

Собирает Telegram-эмодзи из спрайт-листа **или из видео** → .webm VP9 с альфой,
100×100, 2.967 s, без звука, в пределах 64 KB. Нужен только Chrome — кодирует WebCodecs,
ffmpeg не требуется.

## Из видео (Higgsfield и подобное)

```bash
node tools/sprite-to-webm/video-to-webm.mjs <видео.mp4> <forward|pingpong> <выход.webm> \
     [--from 0] [--to 5.2] [--float 3.2]
```

Берёт 89 кадров равномерно по клипу, снимает фон, стабилизирует объект и добавляет парение.

- **Стабилизация.** Генератор дышит: между первым и последним кадром объект уезжает и
  меняет габарит на несколько процентов. Каждый кадр ставится по центру своего bbox,
  масштаб на весь клип один — иначе маска дрожит в размере.
- **Парение** — вертикаль (`--float`, 4.5 px), качание (`--tilt`, 8°) и дыхание масштабом
  (`--zoom`, 5 %). Период равен длине цикла, поэтому колебание замыкается и стык не виден.
  Фазы разведены: качание по косинусу — крен на верхней и нижней точке дуги, а не в момент
  подъёма; масштаб в противофазе к высоте — внизу объект мельче, вверху крупнее.
  Это читается как парение, а не как дрожь.
- **Запас по краям.** Кадр заполняется на 76 %. При наклоне θ вертикальный габарит объекта
  равен H·cosθ + W·sinθ, и на 8° вырастает почти на 10 % — плюс зум, плюс смещение, плюс
  генератор к концу клипа раздувает объект. Без запаса угол маски срезается в крайних фазах.
- **Внутри маски дырок не делается.** Прозрачен только фон вокруг. В исходнике белые
  не только прорези глаз и рта, но и просветы резьбы со щелью носа — вырезав всё белое
  замкнутое, получаешь маску в дырках. Крупные проёмы (глаза, рот) заливаются тёмным,
  мелочь резьбы не трогается. Порог — доля от площади маски, `--minDark` в коде.

```bash
# спрайт уже с альфой
node tools/sprite-to-webm/make.mjs <спрайт.png> <forward|pingpong> <выход.webm>

# спрайт на белом фоне (JPEG из генератора) — сначала снять фон
node tools/sprite-to-webm/keyout.mjs <спрайт.jpg> <очищенный.png>
node tools/sprite-to-webm/make.mjs <очищенный.png> pingpong <выход.webm>
```

## keyout.mjs — снятие фона

Фон ищется **заливкой от краёв**, а не порогом яркости: кожа маски — почти белый ivory,
и любой порог по «белизне» съедает её вместе с фоном, превращая мрамор в контрастный металл.

Отверстия маски — прорези глаз и открытый рот — заливкой от края недостижимы, они замкнуты.
Берутся вторым проходом: замкнутые области фонового цвета крупнее 400 px. Порог по площади
обязателен, иначе блики на коже тоже станут дырками.

Тёмная полость рта снимается третьим проходом. Тени резьбы и золото на маске тоже тёмные,
поэтому кандидат обязан быть замкнутым, широким (w > h) и лежать в нижней половине кадра.
Скрипт печатает, что именно вырезал, — это стоит просматривать глазами.

Край съедается на пиксель: вдоль контура JPEG оставляет светлую кайму, без эрозии
она читается ореолом на тёмном фоне чата.

Номера под кадрами удалять не нужно — они отсекаются при нарезке (см. ниже).

## Как режет

Сетка не задаётся руками — ищется по альфе: колонки и ряды, где нет ни одного
непрозрачного пикселя, считаются границами. Полосы короче 60 px отбрасываются:
это остатки подписей, а не кадры.

Дальше у каждого кадра берётся bbox непрозрачных пикселей, но масштаб на весь
набор **один** — иначе маска «дышит» между кадрами. По X держится центр bbox,
по Y — верхний край: лоб стоит намертво, играет подбородок.

## Раскладка кадров

32 уникальных кадра раскладываются по 89 слотам (89 × 33.3 мс = 2.967 с — с запасом
под лимит Telegram в 3 секунды). Каждый кадр держится 2–3 слота; дубликаты VP9
кодирует почти даром, поэтому длинная анимация стоит не дороже короткой.

`pingpong` доигрывает последовательность назад — цикл замыкается без рывка,
но мимика меняется вдвое быстрее.

## Битрейт

Подбирается лесенкой сверху вниз, пока файл не влезет в 61 KB (запас к лимиту 64 KB).
Цвет и альфа кодируются двумя потоками VP9; альфа уезжает в `BlockAdditional`,
дорожка получает `AlphaMode 1` — как это делает ffmpeg.
