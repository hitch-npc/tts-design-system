# TTS DS R14 — как менять систему (инструкция на одну страницу)

> Цель: менять дизайн-систему быстро и безопасно, не дестабилизируя токены/толщины.
> Главное правило: **`tokens.json` — единственный источник истины.** Блоки `:root` в CSS
> генерируются скриптом и **руками не правятся**.

## Структура

| Файл | Что это | Править руками? |
|------|---------|-----------------|
| `tokens.json` | Все токены сайта (global + dark + light) | **ДА — здесь меняешь значения** |
| `smm.tokens.json` | Токены SMM-слоя (форматы, типошкала), ссылаются на те же примитивы | **ДА** |
| `ds-core-r14.css` | Тёмная тема: `:root` (генерируется) + компоненты (руками) | Только компоненты ниже `:root` |
| `ds-core-r14-light.css` | Светлая тема, аналогично | Только компоненты |
| `ds-smm.css` | SMM: генерируется целиком из `smm.tokens.json` | **НЕТ — генерируется** |
| `tooling/build-tokens.mjs` | Генератор `:root` сайта | по необходимости |
| `tooling/build-smm.mjs` | Генератор `ds-smm.css` | по необходимости |
| `tooling/build-copies.mjs` | Пишет копии для передачи из рабочих файлов (`COPIES`: страница партнёров → `handoff/`) | по необходимости |
| `tooling/drift-check.mjs` | Сторож расхождений (`npm run drift`) | по необходимости |
| `tooling/contrast-check.mjs` | Контраст текста по APCA в обеих темах (`npm run contrast`) | по необходимости |
| `tooling/decisions-review.mjs` | Решения из `DECISIONS.md`, условие пересмотра которых пора проверить (`npm run decisions`) | по необходимости |
| `tooling/drift-hook.mjs` | Хук Claude Code: после правки файла запускает только задетые проверки сторожа; после правки ядра — ещё APCA | по необходимости |
| `tooling/build-emails.py` | Генератор всех писем: рассылки `emails/mailings/*.html` и транзакционные `emails/*.html`, обе группы в светлой теме — Python 3, без зависимостей | **ДА — здесь меняешь письма** |
| `tooling/guardrail.mjs` | Страж правил CLAUDE.md | по необходимости |
| `tooling/security-check.mjs` | Проверка перед публикацией: секреты, личные данные, приватные файлы (`npm run security`) | по необходимости |
| `tooling/build/` | Автономные `ds-tokens-{dark,light}.css` (для Figma/импорта) | генерируется |
| `tooling/backup/` | Бэкап оригиналов до перехода на сборку (локально, в репозиторий не входит) | не трогать |

## Типичные задачи

**Поменять цвет/отступ/радиус/толщину токена**
1. Правишь значение в `tokens.json` (например, `dark.color.accent` или `global.spacing.sp-4`).
2. `npm run build` → `:root` в обоих CSS пересобирается.
3. `npm run lint` → проверка правил.

**Поменять блок на странице (например, расположение театра/площадки на странице события)**
- Это правило **компонента**, а не токен. Правишь нужный класс (`.session-venue-*`, `.venue-*`
  и т. п.) прямо в `ds-core-r14.css` ниже `:root`. Цвета бери только через `var(--…)`.
- Затем `npm run lint`, чтобы не просочились сырой hex / запрещённые ходы.

**Добавить/поменять соц-формат или соц-типошкалу**
1. Правишь `smm.tokens.json` (`smm.canvas.*`, `smm.type.*`, `smm.color.dark.*`, `smm.color.light.*`).
2. Макеты и свечение — строка `TEMPLATES` в `tooling/build-smm.mjs`; цвета только через `var(--smm-…)`.
3. `npm run build` → пересобирается `ds-smm.css`.
4. Пример вёрстки всех постов — `tooling/examples/smm-example.html`. Правила слоя — решение №34 в `DECISIONS.md`.

**Поменять письмо** — рассылку (после спектакля, перенос, напоминание, промокод, подборка) или транзакционное
(после оплаты, накануне, после события)
1. Правишь `tooling/build-emails.py`: общие блоки (`header`, `footer` / `footer_tx`, `button`, `caption`) — сразу во всех
   письмах; текст и порядок блоков — в функции письма (`after_show`, `reschedule`, `reminder`, `promo`, `personal`;
   `payment`, `reminder_tx`, `after_event`).
2. `npm run build:emails` → пересобираются все 8 файлов: 5 в `emails/mailings/` и 3 в `emails/`
   (`emails-all.html` — витрина трёх транзакционных писем). Готовые HTML руками не правятся.
3. Цвета — hex из `tokens.json` (почтовики не понимают `var(--…)`), обе темы — в `THEMES` в начале скрипта:
   поменял токен — поменяй и там. Все письма собираются в светлой теме; тёмную версию рассылок даёт `MAILINGS_THEME = 'dark'`.
   Правила R14 те же: радиус 2px, Cormorant от 22px, кобальт в тексте только крупно.

**Перед тем как «закрыть» правки**
- `npm run check` — собирает в режиме проверки (без записи), сверяет копии, гоняет стража и сторожа расхождений.
- `npm run check:strict` — то же, но сырой `#hex` вне `:root` — ошибка, а не предупреждение. Так проверяет CI.
- Pre-push хук (`.githooks/pre-push`) запускает `security` и сторожа расхождений: при ошибке push отменяется.
- Хочешь добиться идеальной чистоты палитры (вынести сырой hex в токены) — гоняй
  `npm run lint:strict`, он покажет всё, что осталось захардкожено.

## Сторож расхождений (`npm run drift`)

Система живёт не только в ядре: у страницы партнёров, ЛК и автономного cookie-баннера свой CSS, в сборках редизайна
цвета захардкожены, Figma-скрипты дублируют палитру и кнопки, `CLAUDE.md` пересказывает токены. `npm run drift`
(`tooling/drift-check.mjs`) сверяет всё это с эталоном — `tokens.json` → `:root` ядра и правилами компонентов ядра.
Только читает; выход 1, если есть ошибки. Входит в `npm run check` / `check:strict` (CI) и pre-push хук: ошибка сторожа их валит, предупреждения — нет. Офлайн-копий в `~/Downloads` в CI нет, эта проверка там молча пропускается. `--json` — отчёт для агента, `--all` — полный список hex вне палитры в редизайне.

Узкий охват — чтобы не гонять всё:

| Флаг | Что проверяется |
|------|-----------------|
| `--only pages,figma` | только названные проверки |
| `--changed` | проверки, которые задевают файлы, изменённые относительно `HEAD` (вместе с неотслеживаемыми) |
| `--changed main` | то же относительно другой ветки или коммита — например, перед слиянием |
| `--files site/account.html,CLAUDE.md` | проверки для этих файлов (так работает хук) |

Какой файл какие проверки задевает — карта `AFFECTS` в начале `drift-check.mjs`. Правка `tokens.json` или ядра
задевает всё, кроме копий в «Загрузках»; страница партнёров — `pages`, `components`, `copies`; редизайн — `redesign`,
`downloads`; `CLAUDE.md` — `claude-md`, `decisions`; `figma/*.js` — `figma`; `index.html` и HTML в `site/` — `index`.
Новая страница со своим CSS — строка и в `PAGES`, и в `AFFECTS`.

| Проверка | Что сверяется |
|----------|---------------|
| `tokens` | `tokens.json` ↔ `:root` ядра (тот же `build-tokens --check`) |
| `pages` | переменные тем на страницах со своим CSS против ядра: `site/partner-program/partner-program-r14.html` (`.th-d` / `.th-l`), `site/account.html`, `site/cookie-banner/cookie-banner-handoff-standalone.html`. Общие `--foot-*`, `--logo` — против страницы партнёров |
| `components` | тот же селектор (`.btn*`, `.tag*`, `.form-*`, `.theme-toggle*` …) на странице и в ядре: цвет, фон, рамка, шрифт, кегль, жирность, разрядка, регистр, радиус — с подстановкой переменных |
| `copies` | `site/partner-program/handoff/partner-program.html` побайтно равна `partner-program-r14.html` |
| `redesign` | шаблон `site/redesign-v2-*.html` (читается как JSON-строка): блоки токенов против ядра; цвета другой темы вне билета; сводка hex вне палитры с подсказкой «≈ токен» |
| `claude-md`, `decisions` | справочник токенов в `CLAUDE.md` и пары «`--токен` `#hex`» в `CLAUDE.md` / `DECISIONS.md` |
| `figma` | `COLORS`, `PRIMS` в `figma-script.js`; кнопки `STYLES` / `BTN_ST` против `.btn-*` ядра; имена `gv(D,'…')`; запасные `HEX` |
| `index` | битые ссылки витрины; публичные по `.gitignore` страницы `site/`, до которых не дойти от `index.html` |
| `downloads` | офлайн-копии редизайна в `~/Downloads` против `site/` — предупреждение |

Ошибка — значение расходится с эталоном. Предупреждение — похоже на расхождение, но может быть решением
(локальная переменная страницы, отличие правила компонента, страница без карточки в витрине).
Новая страница со своим CSS — строка в `PAGES` в `drift-check.mjs`. Новая побайтная копия — строка в `COPIES` в `tooling/build-copies.mjs`: её пишет `npm run build`, проверяют `npm run check` и сторож. Правила внутри `@media` сверяются только с тем же `@media` в ядре.

**Агент `ds-drift-watcher`** (`.claude/agents/ds-drift-watcher.md`, локально — в публичный репозиторий не входит, модель Sonnet) запускает
скрипт, перепроверяет находки, вручную проходит то, что не автоматизируется (правила «Единого стиля» в разметке,
логотип, согласованность `CLAUDE.md` и `DECISIONS.md`), и отдаёт отчёт «файл — что расходится — эталон — правка».
Сам ничего не правит. Вызов в сессии Claude Code: «проверь расхождения агентом ds-drift-watcher».

Агент работает экономно: по умолчанию `--changed` (или названные файлы и разделы), при нуле находок отвечает одной
строкой, при находках читает только строки вокруг них. Контраст и пересмотр решений — только когда задеты ядро,
токены или `DECISIONS.md`, либо о них просят. Полный прогон всего репозитория — по прямой просьбе «полный прогон»:
он заметно дороже. Сама проверка без агента (`npm run drift`, `check`, CI, pre-push) Claude не расходует вовсе.

## Контраст по APCA (`npm run contrast`)

`tooling/contrast-check.mjs` считает Lc по APCA-W3 0.0.98G для каждой пары «цвет текста — фон» в правилах ядра обеих тем
и сравнивает с минимумом APCA Bronze по роли текста: основной текст (описания, абзацы, подсказки, тосты) — Lc 75,
остальной текст, который нужно прочесть (подписи, метки, цены, кнопки), — 60, крупный от 36px/400 или 24px/700 — 45,
служебный (копирайт, дисклеймер, разделители, плейсхолдер) — 30. Фон без `background` в правиле — фон страницы `--ink`;
цвет, кегль и жирность берутся у базового селектора (`.btn-primary:hover` → `.btn-primary` → `.btn`).
Disabled, проданные места, декоративные слои и классы самого гайда не проверяются.

Отчёт сгруппирован по паре цветов: одна строка — одна пара и список правил, где она стоит. Чаще всего правится токен
(`--n500`, `--n600`), а не правило. `--all` — показать все правила и прошедшие пары, `--json` — для агента.
Выход 1, если есть пары ниже минимума; в `npm run check` пока не входит — сначала нужно решение по серым токенам.
Пример: белый текст на зелёном `#22C55E` (кнопка 14.3.0) — Lc 49 при минимуме 60.

## Пересмотр решений (`npm run decisions`)

`tooling/decisions-review.mjs` читает таблицу «Принятые решения» в `DECISIONS.md` и показывает решения, у которых
за последние 30 дней наступила веха — 1, 3, 6 или 12 месяцев с даты решения. При запуске раз в месяц каждое решение
всплывает четыре раза за год, без файла состояния. Для каждого — условие пересмотра и как его проверить: замер в
репозитории, данные Метрики или поддержки, событие продукта. Решения без условия (`—`) не напоминаются.
`--all` — все решения с возрастом и следующей вехой, `--date 2026-12-01` — как будто сегодня эта дата.

## Хук после правки файла

`.claude/settings.json` (локально, в публичный репозиторий не входит) вешает `tooling/drift-hook.mjs` на каждую правку
файла в сессии Claude Code. Скрипт запускает только проверки, которые задевает правленый файл (`drift-check --files`);
файл вне карты `AFFECTS` пропускается. Ошибки сторожа возвращаются в разговор как блокирующие — правку нужно
донести по копиям или откатить. Без ошибок хук молчит; после правки `tokens.json` или ядра — одна строка-сводка
с числом правил ниже минимума APCA. Выключить — удалить блок `PostToolUse` в `.claude/settings.json`.

## Что страж считает нарушением

- **Ошибка:** `font-weight:300` где угодно, кроме `.smap-zoom-btn` (Manrope — задокументированное исключение R14).
- **Ошибка:** `border-radius > 8px` (система угловатая; потолок `--r-lg = 8px`; `9999px`/`%` можно).
- **Предупреждение (ошибка при `--strict`):** сырой `#hex` вне `:root` — цвета только через `var(--…)`.

Текущий долг: ~78 сырых hex в компонентах (по 39 на тему) — это плашки тегов/тостов/мест и
премиальный ivory `#F5F4EE`. Не блокирует, но это кандидаты на вынос в токены, когда дойдут руки.

Git-репозитория сейчас нет. Если хочешь зафиксировать `v-final` через git:

```bash

git init && git add -A && git commit -m "DS TTS R14 — токены генерируют CSS, страж, SMM-слой"
git tag v-final
```
