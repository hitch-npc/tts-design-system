Cookie consent card

Floating-карточка согласия на cookies. Появляется по центру внизу вьюпорта. Все стили уже лежат в ядре — ds-core-r14.css / ds-core-r14-light.css (секция /* ─── Cookie consent card ─── */). CSS копировать не нужно — только разметку и JS отсюда. Живые превью обеих тем — сразу ниже.

0 · Живое демо

Тёмная тема — ds-core-r14.css
Светлая тема — ds-core-r14-light.css

1 · Разметка

Тексты зафиксированы, не менять. Кнопки — стандартные DS-кнопки.

<div class="cookie-bar" id="cookie-bar" role="region" aria-label="Cookies">

  <div class="cookie-bar-actions">

</div>

3 · Анимации — главное

Все анимации чисто CSS (keyframes уже в ядре), JS только добавляет/убирает классы. Токены: --ease-out: cubic-bezier(.4,0,.2,1), --ease-bounce: cubic-bezier(.34,1.56,.64,1).

ЭлементТриггерKeyframesДлительность / delayEasing

Blob, слой B (синий, ::after)Постоянно cookie-blob-b: дрейф ±26px, rotate −12°…+10°, scale 1–1.28, opacity .25–.85 13s, infinite alternateease-in-out
КарточкаКлик ОКЕЙ / НЕТ cookie-out: opacity 1→0, translate(-50%, 0)→(-50%, 18px), scale 1→.96 280ms / 0--ease-out
  • Каскад появления: карточка → текст (+150ms) → кнопки (+280ms). Все анимации с fill-mode: both — до старта детей не видно.
  • Переливание blob: два слоя с разными периодами (11s и 13s) в противофазе по opacity. Пока фиолетовый гаснет — синий разгорается, паттерн повторяется только раз в ~143s, выглядит нерегулярно. Это дёшево: анимируются только transform и opacity (композитор, без repaint).
  • Неровная форма: каждый слой — два смещённых radial-gradient(closest-side at X% Y%) + filter: blur(30px) + rotate. Никаких border-radius.
  • Центрирование и transform: карточка центрирована transform-ом, поэтому в keyframes входа/выхода translateX(-50%) прописан явно. Если будешь менять анимации — не потеряй его, иначе карточку уведёт вправо.

4 · Логика (JS)

Скрытие — по animationend с проверкой имени анимации (иначе сработает на дочерних keyframes).

const bar = document.getElementById('cookie-bar');

function hideBar(accepted) {
  // TODO(Олег): сохранить выбор, напр.
  // localStorage.setItem('tts-cookie-consent', accepted ? 'yes' : 'no')
  // и не рендерить баннер при следующих визитах
  bar.classList.add('cookie-bar-hide');
  bar.addEventListener('animationend', function onEnd(e) {
    if (e.animationName !== 'cookie-out') return; // важно!
    bar.remove();
    bar.removeEventListener('animationend', onEnd);
  });
}

document.getElementById('cookie-ok').addEventListener('click', () => hideBar(true));
document.getElementById('cookie-no').addEventListener('click', () => hideBar(false));
Персистентность выбора в демо не реализована — на проде решаешь сам (localStorage / cookie), баннер просто не рендерится, если выбор уже сделан.

6 · Доступность и edge cases

  • Контейнер: role="region" aria-label="Cookies". Кнопки — нативные <button>, фокус-порядок: ссылка → ОКЕЙ → НЕТ.
  • Желательно добавить на проде @media (prefers-reduced-motion: reduce): отключить cookie-blob-a/b и заменить вход/выход на простой fade (в ядро DS пока не включено — на твоё усмотрение).
  • Тексты кнопок «ОКЕЙ» / «НЕТ» и основной текст — зафиксированы, не переформулировать.
  • Баннер не должен перекрывать sticky-buy на страницах события: там либо не показывать одновременно, либо поднять cookie-bar выше (bottom с учётом высоты панели).
  • Тема меняется подключением другого CSS-файла — классы и разметка одинаковые для обеих тем.
